# Skill 1 — 歌詞草稿（lyrics-draft）

## 目標
根據 Intake 表單，快速產出結構完整的歌詞草稿。
**此階段不追求完美——歌詞會在 Skill 2 的 Mureka 循環中持續迭代優化。**

## 輸入
- Skill 0 完成的 Intake 表單

## 輸出
- `歌詞草稿.txt`：結構完整的歌詞（含段落標籤）
- 修改建議清單（標記哪些地方是「可替換」的彈性區域）

---

## 歌詞創作原則

### 結構規範
標準歌曲結構（可依需求調整）：

```
[主歌 A]（建立情境，8-12 行）
[主歌 B]（深化情節，8-12 行）
[橋段]（情緒轉折，4-6 行）
[副歌]（情感爆發，8-12 行）
[主歌 C 或橋接]（可選，推進劇情）
[副歌]（第二次，情緒更強）
[橋接 Bridge]（留白或轉折，4-8 行）
[尾聲/Final]（收尾，4-8 行）
```

### 用字風格原則
| 原則 | 說明 |
|------|------|
| 具體畫面 > 抽象情緒 | 寫「晚上九點半空辦公室」而非「好寂寞」 |
| 日常口語 | 避免過度文言或詩意，要像在說話 |
| 押韻自然 | 押韻為輔助，不強迫，寧可不押也不要奇怪的字 |
| 留白給音樂 | 不要每句都塞滿，讓旋律有呼吸空間 |
| 情緒遞進 | 主歌→橋段→副歌，情感要一層層疊高 |

### 各段落功能
| 段落 | 功能 | 技巧 |
|------|------|------|
| 主歌 | 建立場景，讓聽眾進入情境 | 多用具體名詞、時間地點 |
| 橋段 | 情緒轉折點，拉高期待 | 內心獨白、問句 |
| 副歌 | 情感最高點，最記憶點 | 反覆出現的 Hook，要朗朗上口 |
| Bridge | 意外的情緒轉向 | 對比、承認、轉念 |
| 尾聲 | 畫龍點睛，留下餘韻 | 呼應開頭、意象收束 |

## 人工修改空間設計

Claude 輸出歌詞草稿時，會在以下位置標記 `【可替換】`：

```
又是晚上九點半【可替換時間點】
辦公室瞬間攀上了你的陪伴【可替換場景描述】
你笑著說今天也要把工作做完【這句固定，貼近Intake描述】
我坐得冷靜【可替換動作】
心裡卻覺得很暖【固定，情感核心】
```

### 修改流程
```
Claude 輸出草稿
    ↓
人工標記「想改的地方」
    ↓
告訴 Claude：「第X行改成更...的感覺」或「這裡押韻不對」
    ↓
Claude 提供 2-3 個替換選項
    ↓
人工選擇或再調整
    ↓
重複直到滿意
```

## Claude 操作提示

```
根據以下 Intake 表單，幫我創作歌詞草稿：

[貼上 Intake 表單]

要求：
1. 輸出完整歌詞，含段落標籤
2. 在「彈性較高」的行後面標記【可替換】
3. 在每個段落結束後，用一句話說明這段想傳達的核心
4. 儲存為 歌詞草稿.txt
```

### 修改輔助提示
```
幫我修改以下這句歌詞：
「[原句]」

要求：
- 保持同樣的情感（[情緒描述]）
- 押 [X] 韻（若有）
- 字數接近（[N] 個字左右）
- 提供 3 個版本讓我選
```

---

## 注意事項
- 第一版草稿不求完美，先把故事架構撐起來
- 副歌的 Hook 句（最記憶點的那句）要重點打磨
- 中文歌詞要考慮聲調，平仄影響旋律好不好唱
- 保留「嗯嗯嗯」「啊啊啊」等哼唱空間給尾聲/橋段
